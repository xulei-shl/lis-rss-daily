要把这个“每天自动演进、既能往旧主题塞新文章、又能自动孵化新主题，且前端多维分析实时跟进”的核心闭环跑通，工程上最大的雷区只有两个：

1. **不能每天全量重跑聚类（防主题漂移）**：如果每天对全库文章重新跑一次无监督聚类，昨天的“主题 #3（高校馆AI素养）”今天可能变成“主题 #9”，甚至被拆散。这不仅会导致前端 URL 失效、主题列表每天面目全非，还会迫使你每天为所有主题重新调用大模型生成多维分析，Token 成本爆炸。
2. **不能每次打开前端页面才实时算分析（防响应超时）**：多维分析必须在每日后台定时任务（Cron Job）中采取“脏标记增量更新（Dirty-Flag Update）”预先算好落库，前端只做毫秒级的 JSON 读取渲染。

## 二、 核心算法机制：如何做到“老主题稳定演进，新主题自动涌现”？

为了解决“每天都在变”与“自动新增主题”的矛盾，我们采用 **“中心向量路由（Centroid Routing） + 游离池密度孵化（Outlier Pool Incubation）”** 的双轨算法架构。   

### 1. 日常状态：文章是怎么自动归类的？

每个已存在的主题在数据库里都有一个固定的 `topic_id` 和一个代表该主题语义中心的 **中心向量（`centroid_embedding`，即该主题下所有文章向量的均值）**。

每天定时任务跑完“通过过滤 + 全文总结”后，对今日新入库的每篇论文计算向量 $V_{\text{new}}$，并与现有所有主题的中心向量计算余弦相似度：

- **情况 A：命中现有主题（相似度大于或等于阈值 `0.78`）**

  - 直接将该文章绑定到得分最高的 `topic_id`。

  - 使用滑动平均公式更新该主题的中心向量：

    $$V_{\text{centroid}}^{\text{new}} = \frac{N \cdot V_{\text{centroid}}^{\text{old}} + V_{\text{new}}}{N + 1}$$

  - 将该主题标记为 **`is_dirty = TRUE`**（代表今日有新文章进入，需要更新多维分析）。

- **情况 B：未命中任何现有主题（最高相似度小于 `0.78`）**

  - 说明这是一篇探讨新方向或冷门话题的文章，此时**绝不强行塞进老主题**，而是将它的 `topic_id` 设为 `NULL`，放入“游离观察池（Outlier Pool）”。

### 2. 新主题是怎么“无中生有”自动冒出来的？

每天在文章路由结束后，系统检查“游离观察池（`topic_id IS NULL`）”里的文章数量：

- 一旦游离池中的文章数量积累超过一定规模（例如大于或等于 15 篇），系统自动**仅对游离池中的文章**运行一次轻量级的 `UMAP + HDBSCAN` 密度聚类（设置最小成簇阈值 `min_cluster_size = 4`）。   
- **如果有 4 篇以上游离文章在向量空间里抱团成簇**：
  1. 系统自动在主题表中 `INSERT` 一个新主题，将这几篇文章归入该主题；
  2. 调用一次 LLM，根据这几篇文章的总结自动起一个精准的学术主题名称（如*“图书馆专有语料确权与大模型授权”*）；
  3. 标记 `is_dirty = TRUE`，立即触发首次多维分析生成。前端主题列表就会自动多出一个带 `✨ 新兴主题` 标签的新卡片！
- **如果还没凑够密度**：继续留在游离池里等待未来几天的新文章加入。

## 三、 第一步极简数据库改造（仅需新增 1 张表 + 扩展主表 3 个字段）

为了让你以最小改动在现有项目中上线，第一步你甚至不需要动日报表和月报表，只需在现有的文章表上加 3 个字段，并新建 1 张 `topics` 表：

SQL

```
-- 启用 pgvector (如果使用 MySQL/SQLite，可将向量存在本地 Chroma/FAISS，其余字段完全一致)
CREATE EXTENSION IF NOT EXISTS vector;

-- ==========================================
-- 1. 新增：主题聚类与多维分析结果表 (直接支撑前端列表与详情页)
-- ==========================================
CREATE TABLE topics (
    topic_id SERIAL PRIMARY KEY,
    topic_name VARCHAR(255) NOT NULL,          -- LLM 自动生成的学术主题名称
    topic_keywords TEXT[],                     -- 3~5个核心标签词(供前端列表卡片展示)
    status VARCHAR(20) DEFAULT 'NEW',          -- 'NEW'(新孵化) | 'ACTIVE'(活跃) | 'ARCHIVED'
    
    article_count INT DEFAULT 0,               -- 关联文章总数
    today_added_count INT DEFAULT 0,           -- 今日新增文章数(供前端展示 +N 角标)
    centroid_embedding VECTOR(1536),           -- 主题语义中心向量(用于每日新文章快速匹配)
    
    /* 脏标记机制：控制何时重算多维分析，节省90% Token */
    is_dirty BOOLEAN DEFAULT TRUE,             -- 只要有新文章归入，自动置为 TRUE
    last_analyzed_at TIMESTAMP,                -- 上次生成多维分析的时间
    
    /* 前端详情页直接渲染的【多维分析】结构化缓存 */
    multi_dim_analysis JSONB                   -- 包含：演进脉络、方法对比矩阵、共识与空白
);

-- ==========================================
-- 2. 改造：在你现有的文章总结表上新增 3 个字段
-- ==========================================
ALTER TABLE your_existing_articles_table
    ADD COLUMN topic_id INT REFERENCES topics(topic_id), -- 归属的主题ID (NULL代表在游离观察池)
    ADD COLUMN paper_facets JSONB,                       -- 单篇结构化切面(问题/方法/对象/核心发现/局限)
    ADD COLUMN embedding VECTOR(1536);                   -- 基于[研究问题+核心发现]生成的向量
```

## 四、 后端全自动每日流水线设计（4 步定时任务）

你只需要在你现有的每日 RSS 定时脚本（比如每天早上 8:00 跑完“全文总结”之后）后面，追加以下 4 个自动步骤：

### 第 1 步：单篇总结顺带输出切面（入库时执行）

在生成通过论文的全文总结时，让 LLM 同时返回一段轻量 JSON 存入 `paper_facets` 字段，并用 `research_question + core_finding` 计算 `embedding` 向量：

JSON

```
{
  "research_question": "探讨高校学生在科研中使用生成式AI时的引文核查行为特征",
  "method": "眼动实验 + 问卷调查(N=420)",
  "study_object": "双一流高校本硕学生",
  "core_finding": "仅28%学生主动核验AI生成的引文真实性，高年级学生核验率反而更低",
  "limitation": "样本局限于理工科强校，缺乏对人文社科长文本写作场景的对比"
```

### 第 2 步：今日新文章路由归类（Python 核心逻辑，耗时小于 2 秒）

Python

```
import numpy as np

SIMILARITY_THRESHOLD = 0.78  # 归入现有主题的余弦相似度阈值

def route_daily_new_articles(db_conn, today_articles, active_topics):
    """将今日新增文章路由至现有主题，或放入游离池"""
    # 先将所有主题的今日新增计数清零
    db_conn.execute("UPDATE topics SET today_added_count = 0;")
    
    for article in today_articles:
        vec = np.array(article['embedding'])
        best_topic_id, max_sim = None, -1.0
        
        for topic in active_topics:
            centroid = np.array(topic['centroid_embedding'])
            # 计算余弦相似度
            sim = np.dot(vec, centroid) / (np.linalg.norm(vec) * np.linalg.norm(centroid))
            if sim > max_sim:
                max_sim, best_topic_id = sim, topic['topic_id']
                
        if max_sim >= SIMILARITY_THRESHOLD:
            # 1. 命中现有主题：绑定 topic_id，更新主题中心向量，打上 is_dirty 标记
            assign_article_to_topic(db_conn, article['id'], best_topic_id, vec)
        else:
            # 2. 未命中：保持 topic_id = NULL，留在游离池等待孵化
            pass
```

### 第 3 步：游离池扫描与新主题自动孵化（耗时约 5 秒）

Python

```
from umap import UMAP
from hdbscan import HDBSCAN
import numpy as np

def incubate_new_topics_from_outliers(db_conn):
    """当游离池累积足够文章时，自动发现并孵化新主题"""
    outliers = db_conn.query("SELECT id, title, paper_facets, embedding FROM articles WHERE topic_id IS NULL;")
    if len(outliers) < 12:  # 游离文章不足12篇时不启动聚类
        return

    embeddings = np.array([row['embedding'] for row in outliers])
    
    # 降维 + 密度聚类（min_cluster_size=4 代表至少4篇高度相关的文章才算一个新主题）
    umap_embeddings = UMAP(n_neighbors=5, n_components=5, metric='cosine', random_state=42).fit_transform(embeddings)
    labels = HDBSCAN(min_cluster_size=4, metric='euclidean').fit_predict(umap_embeddings)

    # 遍历发现的新簇（label != -1 代表成功成簇，-1 继续留在游离池）
    for cluster_label in set(labels):
        if cluster_label == -1:
            continue
        cluster_docs = [outliers[i] for i, lbl in enumerate(labels) if lbl == cluster_label]
        
        # 调用 LLM 为这几篇文章生成【主题名称】与【核心关键词】
        topic_meta = llm_generate_topic_name(cluster_docs)
        centroid = np.mean([doc['embedding'] for doc in cluster_docs], axis=0).tolist()
        
        # 写入 topics 表，状态设为 NEW，并标记 is_dirty = TRUE 待第4步生成多维分析
        new_topic_id = insert_new_topic(db_conn, topic_meta, centroid, count=len(cluster_docs))
        for doc in cluster_docs:
            db_conn.execute("UPDATE articles SET topic_id = %s WHERE id = %s", (new_topic_id, doc['id']))
```

### 第 4 步：仅对 `is_dirty = TRUE` 的主题更新多维分析（省 Token 的关键）

每天只有进了新文章的老主题、或者刚刚孵化出的新主题（通常每天只有 2~5 个主题变动），才会进入这一步：

- **增量合成策略**：取出该主题下所有文章的 `paper_facets`（注意：只传轻量切面 JSON，不传几千字的全文总结，几十篇文章也才几千 Tokens），让 LLM 一次性输出包含以下 **4 个维度** 的 JSON 存入 `topics.multi_dim_analysis`，随后将 `is_dirty` 重置为 `FALSE`：

| **维度字段名**           | **前端展示形式**            | **生成逻辑**                                                 |
| ------------------------ | --------------------------- | ------------------------------------------------------------ |
| **`topic_overview`**     | 顶部卡片导语                | 200字精炼概括该主题目前的核心研究边界与最新动态。            |
| **`timeline_stages`**    | **维度1：阶段演进轴**       | 按文章发表时间与问题深化逻辑，自动划分为 2~3 个发展阶段，提炼每个阶段的焦点转移。 |
| **`comparison_matrix`**  | **维度2：方法与实证对比表** | 直接聚合各篇的 `method`、`study_object`、`core_finding`，供前端渲染为可筛选对比表格。 |
| **`synthesis_insights`** | **维度3：共识、交锋与空白** | 归纳簇内文献的**学界共识（Consensus）**、**分歧争议点（Controversy）\**以及\**待探索空白（Research Gaps）**。 |

## 五、 历史存量数据的“冷启动”初始化（只需跑一次）

在上线这套每日增量流程之前，针对你数据库里**已经保存的几百/几千篇历史通过论文**，按以下顺序跑一次初始化脚本（`init_clusters.py`）即可完成冷启动：

1. **批量补齐切面与向量**：遍历历史通过文章，基于已有的全文总结提取 `paper_facets` 并计算 `embedding`。
2. **跑一次全量 BERTopic / HDBSCAN**：将历史文章一次性聚合成初始的 15~30 个核心主题簇，计算每个簇的 `centroid_embedding` 写入 `topics` 表；未能成簇的零散文章保持 `topic_id = NULL` 作为初始游离池。
3. **生成初始多维分析**：对这 15~30 个初始主题跑一遍第 4 步的分析合成。
4. **交接给每日定时任务**：从第二天起，全量聚类脚本永久封存，完全由上述第 2~4 步的“中心向量路由 + 游离池孵化 + 脏标记更新”接管。

## 六、 前端接口设计（极简 2 个 REST API）

由于所有复杂计算都在每日定时任务中落库完成，你的后端只需给前端暴露两个极简查询接口，响应时间均在 **20ms 以内**：

- **`GET /api/topics`（主题列表页）**
  - **排序逻辑**：默认按 `today_added_count DESC, status='NEW' DESC, last_analyzed_at DESC` 排序，确保**今天有新文章进入的主题**和**新孵化的主题**永远排在最前面吸引眼球。
  - **返回字段**：`topic_id`, `topic_name`, `topic_keywords`, `status`, `article_count`, `today_added_count`, `last_analyzed_at`。
- **`GET /api/topics/{topic_id}`（主题详情与多维分析页）**
  - **返回字段**：直接返回 `topics.multi_dim_analysis` JSON 字段（直接渲染三个分析维度视图），外加 `SELECT id, title, source_journal, published_at, raw_summary, paper_facets FROM articles WHERE topic_id = {topic_id} ORDER BY published_at DESC`（渲染底部关联文章列表与单篇详情弹窗）。
