# 主题聚类与洞察重建脚本使用说明

本文档汇总了主题聚类与洞察模块在**分层语义聚簇重构**后的两大核心重建工具：
1. **全量清空与从头冷启动重建**：`scripts/cluster-fresh-rebuild.ts`（全新脚本）
2. **既有主题原位洞察层重建**：`scripts/cluster-insight-rebuild.ts`（原有脚本）

---

## 1. 核心架构与重构算法背景

在完成**分层语义聚簇与增量演进（v3.0/v3.1）**重构后，系统底层聚类与洞察生成逻辑如下：
- **一级大主题凝聚阈值**：校准为 $\theta_{\text{init}} = 0.68$（平均连接 UPGMA），杜绝成百篇的“杂烩大主题”；
- **二级子课题凝聚阈值**：校准为 $\theta_{\text{subtopic}} = 0.70$，废弃旧版动态移动质心导致的雪球黑洞吞并，稳定切分出 2~8 个同质子课题；
- **综述 1:1 对齐分面**：深度综述（`cluster_topic_reviews`）与二级子课题 1:1 严格对齐，起编门槛降至 2 篇；
- **子主题独立 LLM 空白分析**：对每个子课题基于全量成员切面与局部矩阵**独立调用一次 LLM** 生成结构化研究空白（`scope = 'subtopic'`、`basis = 'llm_analysis'`），在综述卡片下展示为「依据：LLM分析」；与宏观阶段 B 的全局/跨分面空白（`scope = 'topic'`，Tab 3）按 `scope` 隔离、互不覆写；
- **主题多维研判联动**：先仅对深度综述子簇聚出元簇，再按 `subtopic_key` 与质心挂载子课题/宏观空白，跨分面互证空白成熟度（`closing` / `opening` / `unaddressed`）并升维共性研究议程；
- **平滑脉络展示**：彻底废弃“未识别出连续承接段”的降级文案，子课题全量成员平滑展示。
- **主题洞察版本文件**：每轮完整分析或原位重建完成后，为内容有变化的主题生成一份自包含 HTML 文件（综述与洞察、研究脉络、矩阵与空白、演化趋势四部分），文件名与元数据记录在 `data/cluster-documents/` 与 `cluster_topic_documents` 表，详情页底部可直接下载；内容哈希未变化的重复重建不会产出新文件。

> **前置迁移提示**：v3.1 为 `cluster_topic_gaps` 新增了 `scope` 列（`sql/054_add_gap_scope.sql`），版本文件功能新增了 `cluster_topic_documents` 表（`sql/055_add_cluster_topic_documents.sql`）。在执行下文任意重建脚本前，**请务必先运行一次 `pnpm run db:migrate`**。

## 2. 选型速查表：我该使用哪个脚本？

| 业务诉求 | 推荐命令 | Token 消耗 | 是否改变一级主题 | 是否动底层切面 |
|---|---|---|---|---|
| **想要推倒旧数据，按新阈值 (0.68/0.70) 从头重新聚类并立即看结构** | `pnpm run cluster:fresh-rebuild -- --yes --skip-analysis` | **0 Token (秒级)** | **是 (从 v1 重建)** | **否 (复用已有 930 篇切面)** |
| **彻底清空并重跑全流程（含所有主题的分析、综述、独立空白与研判）** | `pnpm run cluster:fresh-rebuild -- --yes` | 较高 (数百至上千次调用) | **是 (从 v1 重建)** | **否** |
| **连同 930 篇文献的向量特征切面也全部清空重抽** | `pnpm run cluster:fresh-rebuild -- --yes --clean-facets` | 极高 (930 篇重抽+全套分析) | **是** | **是 (全部重抽)** |
| **保留当前一级主题与成员归属，仅按新算法重算子课题与脉络** | `pnpm run cluster:insight-rebuild -- --all --derive-only` | **0 Token (秒级)** | 否 (原位更新) | 否 |
| **针对单个指定主题重跑脉络、两阶段分析、综述、独立空白与多维研判** | `pnpm run cluster:insight-rebuild -- --topic <id\|slug>` | 通常 **5~21 次**调用（随子课题数浮动） | 否 (单主题更新) | 否 |

> **版本文件**：两个脚本在主题处理完成后都会尝试生成/更新 HTML 版本文件；内容与上一版一致时自动跳过。`--dry-run` 不生成；`--skip-analysis` 因主题尚无分析内容，也不会生成。

## 3. 工具一：全量清空与冷启动重建 (`cluster:fresh-rebuild`)

对应脚本：`scripts/cluster-fresh-rebuild.ts`  
对应命令：`pnpm run cluster:fresh-rebuild -- ...`

### 3.1 核心机制与安全保障
1. **强制物理备份**：在执行任何清空前，首先对 SQLite 执行 `wal_checkpoint(TRUNCATE)` 刷盘，并将 `data/rss-tracker.db` 拷贝至 `data/rss-tracker.backup-YYYY-MM-DDTHH-mm-ss.db`。若备份失败则立即中止。
2. **级联清空 14 张聚类层表**：彻底清空主题集合版本、大主题、文献归属链接、脉络、周期指标、两阶段分析、综述、空白、洞察、洞察版本文件元数据及日志表，并将自增序列清零，新版本从 **v1** 开始重新计数；同时删除 `data/cluster-documents/` 下的旧 HTML 版本文件，避免旧文件挂到重建后的同 id 新主题上。
3. **切面资产保护（关键优势）**：默认**保留 `article_cluster_facets`（930 篇文献已抽好的向量切面）**。全库重新凝聚大主题属于纯向量运算，**几秒内即可零成本完成重聚类**，无需重复耗费 API 抽取切面。
4. **安全确认开关**：必须带 `--yes` 参数执行，否则自动拒绝退出。

### 3.2 常用命令示例
```bash
# 1. 预检模式：仅查看当前各表行数、预计备份路径与执行计划（不修改数据库）
pnpm run cluster:fresh-rebuild -- --dry-run

# 2. 【最推荐】清空重构并秒级生成新的一级大主题与二级子课题脉络（0 Token 消耗）
pnpm run cluster:fresh-rebuild -- --yes --skip-analysis

# 3. 全量重构并执行所有主题的 LLM 分析与深度综述
pnpm run cluster:fresh-rebuild -- --yes

# 4. 彻底清空（包含 930 篇文献切面库在内彻底重抽）
pnpm run cluster:fresh-rebuild -- --yes --clean-facets
```

### 3.3 参数说明
| 参数 | 说明 |
|---|---|
| `--dry-run` | 预检模式：仅打印统计数据与执行计划，不修改数据库 |
| `--yes`, `-y` | 确认执行清空与重建（不可逆操作，除 `--dry-run` 外必须提供） |
| `--skip-analysis` | 完成清空与新大主题/子课题聚类后，跳过 Phase A/B 综述与洞察（零 Token 秒级完成；此时不会生成版本文件） |
| `--clean-facets` | 连同 `article_cluster_facets` 一起清空重抽（默认保留） |
| `--analysis-limit N` | 重建后最多分析的主题数上限（默认 200） |
| `-h`, `--help` | 显示帮助 |

## 4. 工具二：既有主题原位洞察层重建 (`cluster:insight-rebuild`)

对应脚本：`scripts/cluster-insight-rebuild.ts`  
对应命令：`pnpm run cluster:insight-rebuild -- ...`

### 4.1 适用场景
对当前活动版本（Active Version）的已有主题，**在不改变一级主题定义、不改变文章归属**的前提下，仅重跑其下游的洞察产物：
1. **派生层（零 Token）**：调用新版 `groupSubtopics` 切分子课题，构建时序脉络并重算周期指标；
2. **两阶段分析**：生成多维方法 × 对象对比矩阵、宏观导读与全局/跨分面空白（`scope = 'topic'`）；
3. **深度综述与子主题独立空白**：按 1:1 对齐的子课题生成分面深度综述，并**对每个子课题独立调用一次 LLM 生成 `scope = 'subtopic'`、`basis = 'llm_analysis'` 的局部空白**（即使 2~5 篇的小主题因样本不足跳过两阶段分析，依然会生成子群综述与分面研究空白；终端 `[综述]` 行会同步输出新增空白数 `空白 N`）；
4. **主题多维研判**：先对综述子簇聚出元簇，再按 `subtopic_key` 与质心挂载子课题/宏观空白，跨分面互证空白成熟度并生成战略洞察报告；
5. **版本文件（零 Token）**：该主题处理完成后，将当前完整内容渲染为自包含 HTML 写入 `data/cluster-documents/`，并记录到 `cluster_topic_documents`；内容未变化时跳过，终端 `[版本文件]` 行会输出 `vN` 或「未变化，跳过」。

> **增量调度 vs 脚本重跑差异**：脚本重跑带有 `force: true` 会强制重算目标主题全部环节；日常周度定时调度不带 `force`，已通过 `input_hash` 校验的旧版子群综述会 **100% 命中缓存（0 Token）**，仅补算或重算变化子主题的独立空白分析与受影响的主题多维研判。

### 4.2 常用命令示例
```bash
# 按数字 id 或 slug 重建单个主题的完整洞察
pnpm run cluster:insight-rebuild -- --topic 97
pnpm run cluster:insight-rebuild -- --topic v2-t-001-aa096e28

# 一次重建多个指定主题（逗号分隔或多次指定）
pnpm run cluster:insight-rebuild -- --topic 97,98,99

# 只重算子课题与脉络派生（零 Token，不调用 LLM）
pnpm run cluster:insight-rebuild -- --topic 97 --derive-only
pnpm run cluster:insight-rebuild -- --all --derive-only

# 全量 LLM 洞察重建（49 个主题逐一调用模型，需 --yes 确认）
pnpm run cluster:insight-rebuild -- --all --yes
```

### 4.3 参数说明
| 参数 | 说明 |
|---|---|
| `--topic <id\|slug>` | 指定主题，可重复或逗号分隔 |
| `--all` | 重建 active 版本下的全部主题 |
| `--derive-only` | 只执行零 Token 派生层（子课题脉络+指标），保留脏标记供后续调度补算 |
| `--dry-run` | 只打印目标主题和预计调用，不写库、不调用 LLM、不生成版本文件 |
| `--yes`, `-y` | 全量重建确认开关（`--all` 且非 `--derive-only` 时必填） |
| `-h`, `--help` | 显示帮助 |

## 5. 推荐重构操作工作流

无论采用哪种工作流，**升级 v3.1 代码后请先执行一次数据库迁移**（为 `cluster_topic_gaps` 增加 `scope` 列，并创建 `cluster_topic_documents` 版本文件表）：
```bash
pnpm run db:migrate
```

### 场景 A：保留现有主题结构，原位升级 v3.1 洞察与独立空白
1. 先挑选 1 个主题验证子主题独立空白分析与主题多维研判效果：
   ```bash
   pnpm run cluster:insight-rebuild -- --topic <id|slug>
   ```
2. 页面刷新检查「本分面局限与研究空白」显示 `依据：LLM分析`、「主题多维研判」无误，且页面底部「历史版本文件」新增 v1 后，再决定全量原位重跑（或等待周度增量跑批自动复用既有综述缓存逐步补齐）：
   ```bash
   pnpm run cluster:insight-rebuild -- --all --dry-run
   pnpm run cluster:insight-rebuild -- --all --yes
   ```

### 场景 B：推倒旧数据，从头冷启动重建（推荐首次部署或调整阈值后使用）

#### 第一步：全量清空并生成全新的主题与分面结构（数秒内完成，0 Token）
```bash
pnpm run cluster:fresh-rebuild -- --yes --skip-analysis
```
- 该命令会自动备份数据库；
- 清空历史混乱旧数据，从 `v1` 开始纯向量重新聚类全库 930 篇文献；
- LLM 自动为全新生成的 30~45 个健康大主题命名；
- 二级子课题（$\theta=0.70$）全量平滑构建脉络；
- **完成后打开浏览器访问 `/clusters`，即可立刻验证全新的主题划分与子课题分面是否纯净**；
- 该模式跳过了分析，因此**不会生成版本文件**，主题详情页底部显示「暂无版本文件」。

#### 第二步：挑选中意的主题按需生成深度综述、独立空白与多维研判
在 `/clusters` 列表中找到感兴趣的主题（如主题 #1 或指定 slug），单独触发完整 LLM 链路：
```bash
pnpm run cluster:insight-rebuild -- --topic 1
```
页面刷新后即可在该主题的「综述与洞察」Tab 中看到 1:1 对齐的子课题综述卡片、标有 **`依据：LLM分析`** 的「本分面局限与研究空白」以及跨分面互证后的「主题多维研判」；页面底部「历史版本文件」会同步出现本次生成的 HTML，可直接下载离线查看四个部分。
