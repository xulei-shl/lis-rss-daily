# 主题洞察重建脚本使用说明

对应脚本：`scripts/cluster-insight-rebuild.ts`
对应命令：`pnpm run cluster:insight-rebuild -- ...`

## 1. 它能做什么

对一个或多个**已有主题**，按当前最新规则依次重跑：

1. **派生层（零 token）**：角度分群、脉络、学术角色、周期指标。
2. **两阶段分析**：主题综述、角度命名与叙述、研究空白。
3. **深度综述**：把角度簇合并成综述组，再生成深度综述。
4. **主题内洞察**：按该主题的综述/空白元簇生成洞察报告。

它**不会**做这些事：

- 不重新抽取 facets；
- 不重新路由文章、不重新聚类主题成员；
- 不创建新版本、不修改主题 slug；
- 不处理已归档版本的主题。

如果要做“重新抽 facets + 重新路由 + 重新聚类”的真正全量重建，请使用现有的 `pnpm run cluster:rebuild`，两者不是同一件事。

## 2. 最常用命令

```bash
# 按 slug 重建一个主题（会调用 LLM）
pnpm run cluster:insight-rebuild -- --topic v1-t-030-f5ffcaaa

# 按数字 id 重建
pnpm run cluster:insight-rebuild -- --topic 30

# 一次重建多个主题：逗号分隔或重复 --topic
pnpm run cluster:insight-rebuild -- --topic 30,v1-t-001-376fabf5
pnpm run cluster:insight-rebuild -- --topic 30 --topic 31

# 只重算角度/脉络/指标，不调用 LLM
pnpm run cluster:insight-rebuild -- --topic 30 --derive-only

# 先看全量目标与预计调用，不写库
pnpm run cluster:insight-rebuild -- --all --dry-run

# 全量重建（必须显式加 --yes）
pnpm run cluster:insight-rebuild -- --all --yes
```

## 3. 参数

| 参数 | 说明 |
|---|---|
| `--topic <id\|slug>` | 指定主题；可重复，也可用逗号分隔多个 |
| `--all` | 重建 active 版本下的全部主题 |
| `--derive-only` | 只执行零 token 的派生层，跳过分析/综述/洞察 |
| `--dry-run` | 只打印目标和预计调用，不写库、不调用 LLM |
| `--yes`, `-y` | 全量 LLM 重建的确认开关；`--all` 且非 `--derive-only` 时必填 |
| `-h`, `--help` | 显示帮助 |

`--topic` 与 `--all` 不能同时使用。

## 4. 执行流程与落库

对每个目标主题：

1. `markTopicDirty()`：先把 `is_dirty` 和 `review_dirty` 置 1，保证中途失败后调度器下一轮还能补算。
2. `rebuildTopicThreads()` + `rebuildTopicMetrics()`：重建 `topic_threads`、`thread_articles` 和周期指标。
3. `runTopicAnalysis({ force: true })`：阶段 A + 阶段 B；成功后清除 `is_dirty`。
4. `runTopicReviews({ force: true })`：按新版“综述组 = 角度并集”生成深度综述；成功后清除 `review_dirty`。
5. `runInsightReports({ force: true, topicIds: [当前主题] })`：只处理当前主题，避免单主题重跑误伤其他主题。

`--derive-only` 会在第 2 步后停止，并**保留脏标记**；之后的日常分析/综述会继续补算 LLM 内容。

## 5. 成本与安全

### 单主题

- 两阶段分析：通常 2 次 LLM 调用；
- 深度综述：按综述组数，通常 1~8 次；
- 主题内洞察：按综述/空白元簇，0~3 次；
- 成员少于分析阈值（当前 6 篇）时会走 `insufficient_data`，不调用分析 LLM。

### 全量

`--all` 会遍历 active 版本全部主题。以当前约 70 个主题估算，仅两阶段分析就至少约 140 次调用，另有综述和洞察调用，成本明显高于单主题。

因此：

- 先跑 `--all --dry-run` 看目标数量；
- 确认后再加 `--yes`；
- 建议执行前备份数据库，例如：
  ```bash
  sqlite3 data/rss-tracker.db ".backup 'data/rss-tracker.backup-before-insight-rebuild.db'"
  ```
- 生产环境不要在没有确认成本的情况下直接跑 `--all --yes`。

## 6. 输出与退出码

脚本会打印每个主题的：

- 派生：角度数、linear/divergent 数、成员数、loose 数；
- 分析：`ok / partial / insufficient_data / failed`；
- 综述：新建、更新、跳过、失败数；
- 洞察：簇数、新建、更新、跳过、失败数。

退出码：

| 退出码 | 含义 |
|---|---|
| `0` | 全部完成 |
| `1` | 有主题在派生/分析/综述/洞察阶段失败，或参数/连接错误 |
| `2` | `--all` 未加 `--yes`，已列出目标但未执行 |

失败主题会保留脏标记，可修复后重跑同一命令。

## 7. 与现有命令的区别

| 命令 | 作用 |
|---|---|
| `cluster:insight-rebuild -- --topic ...` | 重建**指定主题**的洞察层 |
| `cluster:insight-rebuild -- --all --yes` | 重建 active 版本**全部主题**的洞察层 |
| `cluster:refresh --derive-only --force` | 只重算全部主题的派生层（零 token），不跑分析/综述/洞察 |
| `cluster:refresh --analysis-only` | 只处理 `is_dirty=1` 的脏主题，且跳过综述/洞察 |
| `cluster:rebuild` | 创建新版本、重新聚类、强制分析/综述；可能改变主题 id/slug |

## 8. 常见问题

### 提示“当前没有 active 主题集合版本”

先执行：

```bash
pnpm run cluster:init
```

### 提示主题不属于当前 active 版本

脚本只允许重建当前 active 版本的主题。请使用当前版本的 slug，或先切换版本。

### 分析成功但洞察仍为 0

主题内洞察要求至少跨 2 个综述子簇；如果该主题只有 1 篇深度综述，洞察会返回 `skipped`，这是正常行为。

### 全量重建跑到一半失败

失败主题的脏标记会保留。修复 LLM/配置问题后，重新执行相同命令即可；已经成功的主题可以再次执行，脚本会强制重算，但不会改变主题成员。
