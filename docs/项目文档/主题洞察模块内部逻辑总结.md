# 主题洞察模块（Topic Clusters）内部逻辑总结

本文档梳理系统「主题洞察」（代码目录 `src/topic-cluster`，页面路由 `/clusters`）模块的整体设计思想、数据流转机制、核心算法及服务呈现逻辑，为后续系统维护、算法迭代与问题排查提供技术参考。

---

## 1. 业务定位与核心边界

### 1.1 解决的问题
系统原有流水线包含：RSS/期刊/网页抓取 → LLM 过滤 → 翻译与向量化 → 全文总结（AI Summary）→ 每日/周期总结。
然而全文总结产出后，文章之间缺乏主题级别的宏观拓扑结构，无法直接回答以下问题：
1. 某一研究方向存在哪些具体的研究切入角度？
2. 同一角度下的研究脉络如何随时间演进（问题 → 方法 → 发现）？
3. 该主题关注度与方法迁移趋势如何，是否存在研究空白？

本模块以既有全文总结（`articles.ai_summary` 非空）为基础，通过无监督聚类与多维分析，构建可回溯、可检索的主题层级图景。

### 1.2 关键能力交付
| 能力维度 | 业务含义 | 对应数据结构 |
|---|---|---|
| **研究角度** | 同一主题下文章分化的不同切入角度 | 簇内子群（`topic_threads.angle_key`） |
| **研究脉络** | 同一角度上文章的承接与演进关系 | 时序有序链条（`thread_articles`） |
| **研究趋势** | 主题规模变化、质心漂移与方法迁移 | 周期统计与香农熵（`topic_metrics_period`） |
| **研究历史** | 主题内文章时间轴与各自贡献点 | 归属列表与切面明细（`article_topic_links`） |

### 1.3 边界说明
系统内不存储学术引用/参考文献数据。因此本模块呈现的「研究脉络与承接关系」是**基于研究问题、研究方法与研究对象的结构化语义推断**，并非真实的学术引文传承网络。前端展示时显式标注该口径，防止误导。

## 2. 核心架构设计原则

1. **确定性规则前置，LLM 仅用于语义收敛**
   增量路由、凝聚聚类、时序串链、周期统计、方法×对象对比矩阵全部由纯 TypeScript 算法计算完成。LLM 仅负责切面抽取、主题命名与最终叙述生成，且其输出必须严格回链到具体文章 ID。
2. **零新增外部运行时依赖**
   放弃 UMAP / HDBSCAN 等重量级 Python 微服务，采用纯 TypeScript 实现质心路由与平均连接层次凝聚聚类。百篇至千篇量级计算在毫秒级完成，杜绝跨语言 RPC 维护成本。
3. **输出严格防伪与审计防御**
   所有 LLM 交互均通过强 JSON Schema 校验、模板占位符拒绝、引用文章白名单过滤，并记录 `input_hash` 保证分析可复现与防篡改。
4. **不足样本显式降级**
   当主题文章过少（如不足 3 篇）或切面不完整时，显式标记 `insufficient_data` 并仅展示基础统计，不调用 LLM 强行编造虚假洞察。
5. **多归属与版本化身份不可变**
   支持单篇文章归属多个主题（上限 2 个，且具备唯一主归属标记）。主题集合采用版本化管理（`cluster_topic_sets`），规则或模型变更时生成新版本，旧版本归档保留并通过 `cluster_topic_remap` 映射重定向，确保历史 URL 不失效。
6. **异步预计算与零 LLM 耗时只读服务**
   默认按周度（7 天周期，每周一晨间）由调度器旁路异步跑批，计算结果全量落库。用户端 Web 浏览与检索接口纯读库，无实时 LLM 调用，保障毫秒级页面加载。

## 3. 数据模型与表结构

模块迁移定义位于 `sql/045_add_topic_cluster.sql`，通过 Kysely 进行类型化数据交互：

```
cluster_topic_sets ──1:N──► cluster_topics
                                  │
        ┌─────────────────────────┼──────────────────────────┐
        │                         │                          │
        ▼                         ▼                          ▼
article_topic_links        topic_threads            topic_metrics_period
  (多对多关联)                     │                  cluster_topic_analysis
        │                         ▼                  cluster_topic_remap
        │                  thread_articles
        ▼                         │
article_cluster_facets ◄──────────┘
        │
        └──N:1──► articles
```

### 3.1 核心数据表职责
- **`cluster_topic_sets`（主题集合版本表）**
  记录集合版本号（1, 2, 3...）、状态（`active / archived`）、配置快照（`embedding_model`, `embedding_dim`, `facet_contract_version`, `init_threshold`）。任一时刻仅允许一个 active 版本，同时充当配置漂移告警触发器。
- **`cluster_topics`（主题实体表）**
  维护主题身份 `slug`（形如 `v1-t-003-a1b2c3`，不可变）、生成名称、3 至 5 个关键词、质心向量 BLOB（1024 维 float32）、状态（`NEW / ACTIVE / DORMANT / ARCHIVED`）、文章统计数及脏标记 `is_dirty`。
- **`article_cluster_facets`（单篇切面与向量表）**
  存储文章的结构化切面 JSON（研究问题、方法、对象、发现等）、拼接切面文本、1024 维 BGE-M3 向量 BLOB，以及事件发生时间与时间精度（`day / year / ingest`）。
- **`article_topic_links`（文章与主题多归属关联表）**
  连接文章与主题，记录相似度 `similarity`、归属方式（`init / centroid / incubation / reclaim`）、是否主归属 `is_primary`（通过部分唯一索引约束每篇文章在每个版本下恰好一条主归属）及排序位次 `link_rank`。
- **`topic_threads` 与 `thread_articles`（簇内脉络表）**
  记录簇内分化的研究角度（`angle_key`，基于规则归一生成以避免漂移）及其时序脉络；关联表记录链条中前后文章的关系判定（`origin / continue / shift / refute`）与两两相似度。
- **`topic_metrics_period`（周期指标表）**
  记录主题按月（`YYYY-MM`）聚合的新增篇数、累计篇数、质心漂移距离、方法分布香农熵及研究对象分布香农熵。
- **`cluster_topic_analysis`（多维分析缓存表）**
  缓存 LLM 生成的叙述分析结果（`analysis_json`）、纯规则推导的方法×对象对比矩阵（`matrix_json`）、输入指纹 `input_hash` 及状态（`ok / insufficient_data / failed`）。
- **`cluster_topic_remap`（跨版本重定向表）**
  在主题全量重建时，记录旧主题与新主题之间的质心映射关系与相似度，供前端做平滑重定向。

## 4. 核心计算流水线（六步流转）

流水线由 `src/topic-cluster/pipeline/index.ts` 集中编排，包含六个严格有序的执行步骤：

### 步骤 1：切面抽取（Facet Extraction & Embedding）
- **触发源**：扫描已具备全文总结（`articles.ai_summary IS NOT NULL`）且在 `article_cluster_facets` 中无记录的文章。
- **受控词表约束**：调用 LLM（任务类型 `cluster_facet`）抽取 JSON 切面。其中研究方法（`method`）与研究对象（`study_object`）的分类受 `vocab.ts` 中的封闭词表控制（如 `FACET_METHODS` 与 `FACET_OBJECTS`），规范格式为「通用类别（具体样本个案）」，确保后续对比矩阵与分布熵具备统计聚合意义。
- **独立向量计算**：全文总结本身未被主库向量化，本模块调用 BGE-M3 模型为切面拼接文本单独生成 1024 维 float32 向量并存入 BLOB。

### 步骤 2：增量路由（Incremental Routing）
- **判定逻辑**：新抽取切面的游离文章，与当前 active 集合内所有活跃主题的质心向量计算余弦相似度。
- **阈值门禁**：若最大相似度 ≥ 路由阈值 `CLUSTER_ROUTING_THRESHOLD`（默认 0.62），则建立归属关联。
- **多归属配额控制**：每篇文章最多关联 2 个主题。若已达到上限，仅当新相似度高于现有最低相似度时才触发淘汰与替换。重新评定最高相似度链接为 `is_primary = 1`。未达阈值的文章保留在游离池中。

### 步骤 3：游离池孵化（Incubation & Topic Naming）
- **凝聚聚类**：对游离池内所有未归属文章，采用**平均连接凝聚层次聚类（Agglomerative Hierarchical Clustering with Average Linkage）**。避免单链聚类因个别桥接文章产生长条形伪簇。
- **成簇门槛**：簇规模达到 `CLUSTER_INCUBATION_MIN_SIZE`（默认 3 篇）即可孵化为新主题。
- **主题命名与落库**：根据簇内文章切面调用 LLM（任务类型 `cluster_naming`）生成主题名称与 3 至 5 个关键词，计算初始均值质心，生成唯一 `slug` 并落库 `cluster_topics`（状态置为 `NEW`，脏标记置为 1）。

### 步骤 4：定向回捞（Reclaim Mechanism）
- **解决问题**：新主题孵化生成时，其语义中心在历史阶段可能已有部分文章被近似分配到了其他旧主题中，导致新主题先天不全。
- **执行方式**：以新孵化主题的质心为基准，在全部已归属文章中执行一次定向搜索。对满足相似度且未达到多归属上限的文章追加链接，提高新主题的完整度。

### 步骤 5：簇内派生计算（Derivation: Threads & Metrics）
- **触发范围**：仅针对脏标记 `is_dirty = 1` 的主题进行派生增量计算。
- **研究角度分群与时序串链**：
  - 基于文章切面的方法与对象规范键聚合出角度子群（`angle_key`）。
  - 按事件时间（`event_date`）升序排序，计算相邻文章余弦相似度与共享属性。
  - 自动打标演进关系：链首为 `origin`；共享方法与对象为 `continue`；相似度达标但方法或对象变更为 `shift`（方法迁移信号）。
- **周期统计与分布熵**：
  - 按月度切片，计算各周期新增链接数与累计文章数。
  - 计算质心位移距离（`centroid_drift`），量化主题语义漂移。
  - 计算方法与对象的香农熵（Shannon Entropy），量化研究手段的发散与收敛程度。
- **方法×对象对比矩阵**：
  - 纯规则统计交叉频次，生成二维矩阵 JSON。
  - 标记已有研究聚集区与无文章落位的方法对象交叉空白格。

### 步骤 6：多维分析与审计收敛（Multi-Dimensional Analysis）
- **输入指纹防御**：将输入文章切面、脉络结构及矩阵数据进行 SHA-256 哈希计算。若与已存储的 `input_hash` 一致且分析正常，直接跳过计算，节约 LLM 开销。
- **显式降级**：主题文章数低于门槛（< 3 篇）时，置状态为 `insufficient_data`，前端仅渲染统计卡片，不展示生成文本。
- **结构化输出审计**：
  - 校验返回的 JSON 是否符合强 Schema 契约。
  - 拒绝包含占位符的废话（如「待补充 / 暂无发现」）。
  - 核验文本引用的文章 ID 必须在当前簇内白名单中，严防幻觉引用。
- **脏标记清除**：校验通过后落库 `cluster_topic_analysis`，并重置 `cluster_topics.is_dirty = 0`。若校验失败保留脏标记，下轮继续重试。

## 5. 调度体系与服务接口

### 5.1 调度器配置
- 模块调度器为 `src/topic-cluster-scheduler.ts`（类名 `TopicClusterScheduler`），继承自 `src/utils/base-scheduler.ts`。
- 执行周期升级配置为**每周执行一次（7 天更新周期）**，默认每周一晨间 `08:30`（Cron 表达式通过 `CLUSTER_SCHEDULE` 配置，默认 `'30 8 * * 1'`），排在每日全文总结流水线之后，错开 LLM 访问峰值与 SQLite 写锁争用。同时支持管理员通过 `runNow()` 手动即时触发。
- 全流程涉及的 LLM 调用（切面抽取 `cluster_facet`、主题命名 `cluster_naming`、学术综述 `cluster_analysis` 与范式即时钻取 `cluster_matrix_review`）均在系统 `/settings` 的「AI 配置 -- LLM 配置和系统提示词」中实现统一的任务类型分配与提示词在线管理。

### 5.2 只读 API 接口设计
路由挂载于 `src/api/routes/cluster-topics.routes.ts`，面向所有登录角色（admin / user / guest）开放：
- `GET /api/cluster-topics`：支持分页检索与排序（按活跃度 `recent`、文章数 `size`、名称 `name`）。
- `GET /api/cluster-topics/overview`：返回全库主题总数、文章覆盖总数、活跃脉络数与未归属游离篇数。
- `GET /api/cluster-topics/:slugOrId`：按 slug 或数字 ID 获取主题全貌（基本信息、多维分析叙述、脉络时间链条、周期趋势指标、对比矩阵）。

**接口特性**：全部接口均为**纯数据库读操作**，响应耗时为毫秒级，运行期间不产生任何动态 LLM 计费与网络开销。

## 6. 维护与诊断指引

### 6.1 常用维护脚本
- `scripts/cluster-init.ts`：冷启动全量初始化脚本，用于首次对历史积压的全文总结文章建库与生成主题。
- `scripts/cluster-validate.ts`：系统巡检与验证脚本，校验主题主归属唯一性、多归属上限、质心向量完整性与脏标记积压情况。
- `scripts/test-topic-cluster-domain.ts`：纯算法单测脚本，在不依赖数据库与外部网络的情况下校验余弦计算、凝聚聚类与串链状态机。

### 6.2 常见问题排查
1. **新总结文章未进入主题**：
   - 检查文章 `articles.ai_summary` 是否生成。
   - 检查 `article_cluster_facets` 是否存在该文章记录（若无说明处于切面抽取排队中）。
   - 检查该文章切面与现有主题质心的最大余弦相似度是否低于 0.62（低于则暂存游离池，等待累计达 3 篇后自动孵化）。
2. **多维分析出现 insufficient_data**：
   - 该主题关联的唯一文章数不足 3 篇，系统主动触发保护性降级，属于预期机制。
3. **配置漂移告警（Config Drift）**：
   - 当修改了全局 Embedding 模型（如从 BGE-M3 切换）或切面契约版本时，流水线启动会通过 `detectConfigDrift` 打印告警。此时应根据业务计划执行新版本重建，系统不会静默自动重建以防止主题标识漂移。
