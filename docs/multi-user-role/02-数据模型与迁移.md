# 多用户角色扩展方案 — 数据库迁移

## 0. 无需改动的表（已有 `user_id`，数据已按用户隔离）

以下表**结构和数据均无需迁移**，多用户场景下可直接使用，只需调整路由权限：

| 表 | 作用 | 说明 |
|----|------|------|
| `system_prompts` | 系统提示词 | 每个用户独立管理自己的提示词模板 |
| `llm_configs` | LLM 配置 | 每个用户独立配置自己的 API key / provider / model |
| `topic_domains` | 主题领域 | 每个用户独立定义主题分类 |
| `topic_keywords` | 主题关键词 | 每个用户独立定义关键词 |
| `settings` | 系统设置 | 每个用户的通知开关、日程配置等 |
| `telegram_chats` | Telegram 聊天绑定 | 每个用户绑定自己的聊天列表 |
| `wechat_webhooks` | 企业微信 Webhook | 每个用户配置自己的 Webhook |
| `daily_summaries` | 每日总结 | 每个用户独立生成和查看 |
| `deepsearch_tasks` | 深度检索任务 | 每个用户独立的检索任务 |
| `users` | 用户表 | 新增 `user` 角色，无需改表结构 |

## 1. 新建表

### `source_subscriptions` — 用户-源订阅关系

```sql
CREATE TABLE IF NOT EXISTS source_subscriptions (
  user_id INTEGER NOT NULL,
  source_type TEXT NOT NULL CHECK(source_type IN ('rss','journal','keyword','email')),
  source_id INTEGER NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (user_id, source_type, source_id),
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
```

### `user_articles` — 用户-文章状态

```sql
CREATE TABLE IF NOT EXISTS user_articles (
  user_id INTEGER NOT NULL,
  article_id INTEGER NOT NULL,
  filter_status TEXT DEFAULT 'pending' CHECK(filter_status IN ('pending','passed','rejected')),
  filter_score REAL,
  filtered_at DATETIME,
  is_read INTEGER DEFAULT 0,
  is_starred INTEGER DEFAULT 0,
  rejected_at DATETIME,
  rejection_reason TEXT,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (user_id, article_id),
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY (article_id) REFERENCES articles(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_user_articles_user_id ON user_articles(user_id);
CREATE INDEX IF NOT EXISTS idx_user_articles_article_id ON user_articles(article_id);
CREATE INDEX IF NOT EXISTS idx_user_articles_filter_status ON user_articles(user_id, filter_status);
CREATE INDEX IF NOT EXISTS idx_user_articles_is_read ON user_articles(user_id, is_read);
```

## 2. 存量数据迁移

> **原则**：所有存量文章、源均默认绑定 admin 用户（user_id=1）。

```sql
-- 迁移文章状态：所有存量文章默认属于 admin
INSERT INTO user_articles (user_id, article_id, filter_status, filter_score, filtered_at, is_read)
SELECT 1, id, filter_status, filter_score, filtered_at, is_read
FROM articles;

-- 迁移源订阅关系：所有存量源默认属于 admin
INSERT INTO source_subscriptions (user_id, source_type, source_id)
SELECT user_id, 'rss', id FROM rss_sources;

INSERT INTO source_subscriptions (user_id, source_type, source_id)
SELECT user_id, 'journal', id FROM journals;

INSERT INTO source_subscriptions (user_id, source_type, source_id)
SELECT user_id, 'keyword', id FROM keyword_subscriptions;

INSERT INTO source_subscriptions (user_id, source_type, source_id)
SELECT user_id, 'email', id FROM email_sources;
```

## 3. 日志表字段补齐

多种日志表缺少 `user_id` 或查询路径有漏洞，需统一补齐：

### `article_filter_logs` 增加 `user_id`
```sql
ALTER TABLE article_filter_logs ADD COLUMN user_id INTEGER REFERENCES users(id);
UPDATE article_filter_logs SET user_id = 1 WHERE user_id IS NULL;
```

### `article_process_logs` 增加 `user_id`
```sql
ALTER TABLE article_process_logs ADD COLUMN user_id INTEGER REFERENCES users(id);
-- 存量数据通过 articles 关联补上
UPDATE article_process_logs SET user_id = (
  SELECT COALESCE(rss_sources.user_id, journals.user_id, keyword_subscriptions.user_id, email_sources.user_id, 1)
  FROM articles
  LEFT JOIN rss_sources ON articles.rss_source_id = rss_sources.id
  LEFT JOIN journals ON articles.journal_id = journals.id
  LEFT JOIN keyword_subscriptions ON articles.keyword_id = keyword_subscriptions.id
  LEFT JOIN email_sources ON articles.email_source_id = email_sources.id
  WHERE article_process_logs.article_id = articles.id
) WHERE user_id IS NULL;
```

### `email_fetch_logs` 增加 `user_id`（当前无此字段，且查询无任何用户作用域，**严重泄露**）
```sql
ALTER TABLE email_fetch_logs ADD COLUMN user_id INTEGER NOT NULL DEFAULT 1 REFERENCES users(id);
-- 存量数据通过 email_sources 关联补上
UPDATE email_fetch_logs SET user_id = (
  SELECT email_sources.user_id FROM email_sources WHERE email_sources.id = email_fetch_logs.email_source_id
) WHERE user_id = 1;
```

### `journal_crawl_logs` 增加 `user_id`
```sql
ALTER TABLE journal_crawl_logs ADD COLUMN user_id INTEGER REFERENCES users(id);
UPDATE journal_crawl_logs SET user_id = (
  SELECT journals.user_id FROM journals WHERE journals.id = journal_crawl_logs.journal_id
) WHERE user_id IS NULL;
```

### `keyword_crawl_logs` 增加 `user_id`
```sql
ALTER TABLE keyword_crawl_logs ADD COLUMN user_id INTEGER REFERENCES users(id);
UPDATE keyword_crawl_logs SET user_id = (
  SELECT keyword_subscriptions.user_id FROM keyword_subscriptions WHERE keyword_subscriptions.id = keyword_crawl_logs.keyword_id
) WHERE user_id IS NULL;
```

## 4. 日志查询统一策略

迁移后，所有日志查询统一使用 `user_id` 字段直接过滤，不再通过源表 JOIN 间接作用域：

```sql
-- 旧模式（各表不一致）
WHERE rss_sources.user_id = ?  -- 间接 JOIN

-- 新模式（统一）
WHERE <log_table>.user_id = ?
```
