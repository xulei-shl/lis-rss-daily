# 多用户角色扩展方案 — 权限与中间件

## 1. 类型定义

```typescript
// src/middleware/auth.ts

export type UserRole = 'admin' | 'user' | 'guest';

const ROLE_HIERARCHY: Record<UserRole, number> = {
  admin: 3,
  user: 2,
  guest: 1,
};
```

## 2. `effectiveUserId` 逻辑

```typescript
// 在 requireAuth / optionalAuth 中：
req.effectiveUserId = payload.role === 'guest' ? 1 : (payload.userId || 1);
```

- `guest` → 映射到 admin(user_id=1)，读取 admin 数据
- `user` → 使用自身 userId
- `admin` → 使用自身 userId

## 3. 中间件函数

| 中间件 | 允许的角色 | 用途 |
|--------|-----------|------|
| `requireAuth` | admin / user / guest | 读取操作 |
| `requireAdmin` | admin | 系统级写操作 |
| `requireUser` | admin / user | 用户级写操作 |
| `requireWriteAccess` | admin | 同 `requireAdmin`（保留兼容） |
| `optionalAuth` | 所有人（含未登录） | 搜索页等 |

```typescript
/**
 * 要求登录用户为 admin 或 user（可写用户级数据）
 * guest 被拒绝
 */
export function requireUser(req: AuthRequest, res: Response, next: NextFunction): void {
  if (!req.user) {
    res.status(401).json({ error: 'Unauthorized' });
    return;
  }
  if (!hasRole(req.user.role!, 'user')) {
    res.status(403).json({ error: '访客用户只能读取数据，无法执行此操作' });
    return;
  }
  next();
}
```

## 5. 页面路由（`web.ts`）权限调整

| 路由 | 旧逻辑 | 新逻辑 |
|------|--------|--------|
| `/settings` | `role !== 'admin'` 重定向 | `role === 'guest'` 重定向 |
| `/topics` | `role !== 'admin'` 重定向 | `role === 'guest'` 重定向 |
| `/filter-stats` | `role !== 'admin'` 重定向 | `role === 'guest'` 重定向 |

`user` 和 `admin` 均可访问上述页面。
