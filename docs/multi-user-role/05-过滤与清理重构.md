# 多用户角色扩展方案 — 过滤与清理重构

## 1. 过滤管道重构

### 当前流程

```
saveArticles() → triggerAutoFilter()
  → filterArticle() 写入 articles.filter_status
  → 若 passed → processArticle()
```

### 新流程

```
saveArticles() → linkArticlesToSubscribedUsers() → triggerAutoFilter(triggerUserId)
  → filterArticle() 写入 user_articles.filter_status
  → 若 passed → processArticle()
```

### `filterArticle()` 改动

```typescript
async function filterArticle(
  articleId: number,
  userId: number,       // 新增：为哪个用户过滤
  source: FilterInput
): Promise<FilterResult> {
  // ... LLM 评估逻辑不变 ...
  
  // 写入 user_articles 而非 articles
  await db.updateTable('user_articles')
    .set({
      filter_status: result.status,
      filter_score: result.score,
      filtered_at: new Date().toISOString(),
      updated_at: new Date().toISOString(),
    })
    .where('user_id', '=', userId)
    .where('article_id', '=', articleId)
    .execute();
  
  return result;
}
```

### 过滤日志关联

`article_filter_logs` 新增 `user_id` 字段，记录过滤是为哪个用户执行的。

## 2. 拒绝/清理重构

### 当前逻辑

- 查 `articles WHERE filter_status = 'rejected' AND source_id = ?`
- 物理删除 `articles` 行，CASCADE 清除关联数据
- 归档到 `rejected_articles`

### 新逻辑

```typescript
async function cleanupSource(sourceType: string, sourceId: number) {
  // 1. 查该源所有订阅用户中被拒绝的文章
  const rejectedEntries = await db
    .selectFrom('user_articles')
    .innerJoin('articles', 'articles.id', 'user_articles.article_id')
    .select([
      'user_articles.user_id',
      'user_articles.article_id',
      'user_articles.filter_status',
      'user_articles.rejected_at',
      'articles.title',
      'articles.url',
      // ... 其他 article 字段
    ])
    .where('user_articles.filter_status', '=', 'rejected')
    .where(this.getSourceColumn(sourceType), '=', sourceId)
    .execute();

  for (const entry of rejectedEntries) {
    // 2. 归档到 rejected_articles（新增 user_id 字段）
    await archiveToRejected(entry);

    // 3. 删除 user_articles 行
    await db.deleteFrom('user_articles')
      .where('user_id', '=', entry.user_id)
      .where('article_id', '=', entry.article_id)
      .execute();

    // 4. 检查文章是否还有其他用户引用
    const remaining = await db
      .selectFrom('user_articles')
      .select(db.fn.countAll().as('count'))
      .where('article_id', '=', entry.article_id)
      .executeTakeFirst();

    if (Number(remaining?.count ?? 0) === 0) {
      // 无用户引用 → 物理删除文章
      await db.deleteFrom('articles')
        .where('id', '=', entry.article_id)
        .execute();
    }
  }

  // 5. 更新清理统计（per-user）
  await updateCleanupStats(rejectedEntries);
}
```

### 关键变化

| 项目 | 旧行为 | 新行为 |
|------|--------|--------|
| 拒绝状态存储 | `articles.filter_status` | `user_articles.filter_status` |
| 自动标记已读 | `articles.is_read = 1` | `user_articles.is_read = 1` |
| 清理目标 | 物理删除文章 | 删除 user_articles 行 |
| 物理删除时机 | 清理即删除 | 零用户引用时才删除 |
| 归档 user_id | 无 | 记录谁拒绝的 |
| 清理统计 | per-source | per-user + per-source |

## 3. `batchUpdateFilterStatus()` 改动

```typescript
// 新签名：增加 userId 参数
export async function batchUpdateFilterStatus(
  userId: number,
  updates: Array<{
    articleId: number;
    status: 'passed' | 'rejected';
    score?: number;
  }>
): Promise<void> {
  const db = getDb();
  const now = new Date().toISOString();

  for (const update of updates) {
    const setFields: any = {
      filter_status: update.status,
      filter_score: update.score ?? null,
      filtered_at: now,
      updated_at: now,
    };
    if (update.status === 'rejected') {
      setFields.is_read = 1;
      setFields.rejected_at = now;
    }

    await db
      .updateTable('user_articles')
      .set(setFields)
      .where('user_id', '=', userId)
      .where('article_id', '=', update.articleId)
      .execute();
  }
}
```
